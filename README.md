# d27o — Software Engineer

Персональное портфолио на **Next.js App Router, React и TypeScript**.
Страницы полностью генерируются при сборке; сервер Next.js для хостинга не нужен.
Профессиональный стек автора указан отдельно: Vue 3, TypeScript, Pinia, Vitest, Playwright.

## Локальный запуск

Нужен Node.js 24 (версия задана в `.nvmrc`).

```sh
npm ci
npm run dev
```

Разработка: http://127.0.0.1:3000/.
Проверка готовой статической версии:

```sh
npm run build
npm run typecheck
npm test
npm run preview
```

Просмотр: http://127.0.0.1:4173/. Команда preview обслуживает **готовые файлы из `out/`**,
включая прямые переходы по адресам и страницу 404. После изменения исходников сборку нужно повторить.
`npm start` / `next start` для статического экспорта не используются.

## Где редактировать

- `lib/site.ts` — роль, метаданные, контакты, локация «Москва», текущий стек и навигация.
- `lib/experience.ts` — подтверждённые работодатели, периоды и описание опыта; общие данные для главной и «Обо мне».
- `lib/projects.ts` — анонимные коммерческие кейсы; результат всегда виден, дополнительные подробности раскрываются отдельно.
- `app/page.tsx`, `app/about/page.tsx`, `app/contact/page.tsx` — основные страницы.
- `content/posts/*.md` — статьи; `slug` сохраняет прежний адрес публикации.
- `lib/archive.ts` — данные ранних проектов; `components/ArchiveProject.tsx` — их страница.
- `app/globals.css` — оформление; `components/Header.tsx` — адаптивная навигация.
- `public/src/` — изображения и шрифты с сохранением прежних публичных URL.
- `tests/export.test.mjs` — проверки маршрутов, метаданных, ресурсов, RSS и контента в готовой сборке.

Сохранены `/`, `/about/`, `/contact/`, `/blog/`, `/boevaya-classica/`, `/grant-ib/`,
`/post-number-0/`, `/bootstrap-5-alpha/`, `/feed.xml` и `/404.html`.
Добавлены статические `sitemap.xml` и `robots.txt`.

## Сборка и публикация

`output: 'export'` и `trailingSlash: true` создают каталог `out/` для статического хостинга.
Изображения работают без серверного оптимизатора; `.nojekyll` сохраняет доступность `_next/` на GitHub Pages.
Ruby, Jekyll, Liquid и Sass больше не нужны.

**Публикация не настроена намеренно.** Workflow `check.yml` только проверяет PR:
установка зависимостей, сборка, TypeScript и тесты. У него только `contents: read`;
нет шага деплоя и прав `pages: write`. Настройки Pages не изменялись.
Не сливать PR и не публиковать сайт до просмотра владельцем и отдельного разрешения.
При дальнейшем подключении Pages публиковать именно содержимое `out/`, а не исходники.

## Конфиденциальность

Коммерческие кейсы обобщены. Не добавлять названия закрытых продуктов, заказчиков,
исходный код, скриншоты, внутренние метрики и детали реализации без разрешения.
Желаемая роль не выдаётся за историческую должность; текущий стек не приписывается
конкретным работодателям без подтверждения. Старые статьи сохранены как архив.
